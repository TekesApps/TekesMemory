# TekesMemory 0.2.1

日期：2026-10-13。本次以 GitHub PR 合并源码，并以 `v0.2.1` tag 标识主线发布；不发布独立打包脚本或预构建二进制，也不运行 crates.io publish。

## 变更与兼容

- HTTP、stdio 和客户端协议实现迁移到精确锁定的官方 `rmcp =3.5.1`，服务仍仅开放 MCP `2025-11-25`，HTTP `/mcp` 保留 JSON 响应。
- 客户端必须按 `initialize` → `notifications/initialized` → 工具调用完成握手；旧 stdio 宽松接受的未 initialized 序列现在被拒绝。
- 旧 `clientInfo={}` 兼容适配保留；非对象等无效 MCP envelope 由 SDK 拒绝。业务参数错误仍返回 `isError` 和结构化 code，未知工具返回协议错误。
- `memory.reconcile_effect` 完整校验既有 schema，额外未知字段现在返回 `invalid_argument`；合法参数及回执结果不变。
- 关闭 SDK 会话恢复、SSE 重试及 reqwest 自动重试；超时预算包含握手，写入结果未知时须显式查询 effect receipt。Client Drop 在剩余预算内有界等待 DELETE 确认。

Store、数据库 schema 1、业务 schemas、配置和 adapter 未变；保留 principal/scope 授权、权限热撤销、唯一 owner 写锁、幂等及持久 effect receipts。CLI 参数和生命周期合同保持既有行为。

## 验证与边界

迁移验收通过：50 项集成测试、2 项官方 TypeScript SDK HTTP/stdio 测试、真实 Kernel HTTP/stdio MCP 互操作、1 项真实 Kernel worker 测试（本地 Provider fixture）、Clippy 和格式检查。完整命令、源码及二进制来源、生命周期 smoke 的旧二进制边界见 [验证记录](../verification.md)。

0.2.1 发布前再次执行并通过 locked 全目标测试（50 项集成，lib/bin/examples 独立单元为 0 项）、2 项官方 SDK 测试、真实 Kernel HTTP/stdio MCP 与 1 项 worker 集成、Clippy、fmt、diff、CLI 版本及依赖元数据检查；所有命令 exit 0。最终 CLI 返回 `tekes-memory 0.2.1`。

本轮 debug 验证二进制 SHA256：`e7960c206d1462018d66d4422e98914508ffb970f2a24da5e2bbea4d50a19914`；它不是预构建发布资产，也不同于迁移阶段的旧二进制哈希。日志保存在 `/tmp/tekesmemory-release-0.2.1-{tests,clippy,build,sdk,kernel-mcp,kernel-worker}.log`，可能被系统清理。仓库没有测试 CI workflow；GitHub Dependency Graph 成功不等同于测试 CI 通过。

未验收：生产/日常部署、真实模型 Provider、Linux 实机、DSH 自动生命周期、长期记忆质量、长时会话老化及满载压力。旧独立打包验证产物仅是本地历史证据，不作为 0.2.1 的发布二进制。
