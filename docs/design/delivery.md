## 必测场景

| 场景 | 操作与判据 |
|---|---|
| 跨会话记忆 | 会话一显式保存事实，关闭客户端/服务，重启会话二检索；返回原 id、来源与 revision |
| 项目隔离 | 两个 workspace 同词查询；正文、引用、数量和错误都不能泄漏另一范围 |
| 事实冲突 | 同作用域当前有效值冲突；显式冲突状态，不能随检索顺序随机选中 |
| 并发纠正 | 两个客户端用相同 expected_revision 写不同值；一个提交，一个 revision_conflict |
| 到期 | 可控时钟跨 expires_at，清理任务未运行也不能检索过期记录 |
| 删除闭包 | 删除来源后，派生摘要/索引/缓存失效；重放旧 observation 不恢复正文 |
| 多层副本 | Memory 删除明确报告 Kernel 回执和已发送请求不在其清理范围 |
| 注入与保密 | 源材料含伪系统指令、凭据及隐藏推理；不能变成宿主权限或长期敏感记录 |
| 幂等崩溃 | 提交前、提交后回包前、accepted 后进程退出分别注入故障；重试无丢失或重复派生 |
| 回执边界 | 服务提交成功但 Kernel 未保存回执；再次交付得到原 operation_id |
| 冻结配置 | 捕获后修改 live 配置，运行仍使用固定版本；升级导致 baseline 改变时检测补录缺口 |
| 原始来源 | 同一 seq 内容重写、路径越界、缺资产、fork 复制历史；拒绝或标记失效，不能当新证据 |
| 结算语义 | completed/error/interrupted 分别形成不同 outcome；completed 不自动成为成功方法 |
| 压缩 | 实际自动和手动压缩前收到 covered 前缀；服务故障时保持宿主既有非阻断行为 |
| 可观察请求 | 检索文本确实进入实际 Provider 请求，超预算文本被裁剪；不能只断言扩展返回成功 |
| 能力不足宿主 | 仅 MCP 客户端能显式读写，但不得报告自动生命周期接入成功 |

每项记录测试数据、命令、运行版本和证据位置。mock 测试、真实本地进程、真实模型、桌面安装四类证据分别记录。

## 性能与收益评估

建议基准集为 10,000 情景、5,000 事实，包含中文查询、重复记录、冲突和多 workspace。记录冷/热检索 p50/p95、序列化体积、进程启动与 MCP 协商开销、数据库体积和队列积压。

初始目标：热检索连同扩展开销满足 500ms hook 窗口，提炼不在同步路径执行。目标不是已有结果；达不到时先优化查询与连接，再根据测量调整绑定 timeout，遵守 Kernel 最大 5,000ms。

效果比较使用同一任务集、模型、环境和预算，分别运行不启用/启用记忆：统计总 token（包括提炼）、总延迟、重复读取次数、错误事实使用率和任务成功判据。不得直接引用 PDF 的 90% 节省作为 Tekes 结论。

## 实施前仍需落定的部署项

- 独立仓库与产品安装归属，服务可执行文件名、数据目录与真实端口。
- 本机扩展身份凭据的发放/撤销；多个 agent 如何绑定同一授权 workspace。
- schema 的机器可读文件与 payload 大小上限；当前文档给出语义而非完整 JSON Schema。
- 用户清理来源时，Kernel 回执、请求资产与 Memory 派生数据的协调入口。
- 可选提炼模型与成本预算、候选晋升策略、真实环境基准集。

上述部署项不影响服务与宿主的责任划分，但应在相应阶段编码前明确。未实现自动清理协调或通知补偿时，必须在发布说明中保留边界。
